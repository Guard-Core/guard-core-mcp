# guard-core-go

The Go port of the guard-core security engine. Module `github.com/rennf93/guard-core-go/v4`, directive `go 1.25.0`, dependencies on `dlclark/regexp2`, `redis/go-redis/v9` and `golang.org/x/text`.

## Install

```sh
go get github.com/rennf93/guard-core-go/v4@v4.2.0
```

Tagged `v4.2.0` and served by the Go module proxy under the `/v4` major path (v2+ modules require the major-version suffix in the import path). Version is carried entirely by the git tag; there is no version constant in the Go source.

## Setup

The engine pattern used by every Go adapter:

1. `cfg := guardcore.DefaultSecurityConfig()`
2. `engine, err := guardcore.NewEngine(cfg)`
3. `engine.Initialize()`
4. Hand the engine to an adapter constructor such as `nethttp.New(engine)`.

Direct detection entry point: `guardcore.Detect(content, ip, context)` returning a `DetectResult`. Route-level configuration registers through `engine.Routes.Register`, and adapters pick route ids off the request context with their `WithRouteID(ctx, id)` option.

## Conformance

`conformance/guard-core-spec-4.1.0/` vendors the frozen spec 4.1.0 fixture corpus: 219 cases across 17 suites (the 12 detect suites plus the 5 pipeline suites pipeline_ip_control, pipeline_rate_limits, pipeline_detection_response, pipeline_headers_cors and pipeline_behavior_rules, run by `pipeline_test.go`). `cases/index.json` pins `spec_version` 4.1.0. `CORPUS.md` states the expected values were generated by the Python reference engine (enhanced 4.x detection path) and must never be hand-written.
