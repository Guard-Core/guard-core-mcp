# guard-core-rs

The Rust port of the guard-core detection engine. Cargo workspace (`crates/*`), edition 2024, MSRV 1.92, `unsafe_code = "forbid"`.

## State

Tagged `v4.4.0` with both publishable crates on crates.io. Workspace members:

- `guard-core-rs` 4.4.0: the facade crate, re-exporting `detect`, `compiler`, `preprocessor` and `semantic` from the engine.
- `guard-core-engine` 4.4.0: the engine crate, the integration point the framework adapters depend on.
- `guard-core-python` 4.4.0: PyO3 cdylib binding, kept `publish = false`.
- `guard-core-benchmark` and `guard-core-conformance`: internal.

The README documents the two published crates and links the adapter repos.

## Setup

The adapters (tower-guard-rs, axum-guard-rs, actix-guard-rs, rocket-guard-rs) depend on the engine crate directly:

```toml
guard-core-engine = "4.4.0"
```

Engine view: `detect(content, context, config)` with `DetectConfig::max_full_scan_bytes` (262,144 bytes, the ecosystem default). The engine never scans the HTTP method, and its header view skips `sec-*` plus a fixed set of standard hop headers.

## Conformance

`conformance/guard-core-spec-4.1.0/` holds the spec 4.1.0 corpus vendored from the reference (375 cases across 21 suites, generated by reference engine 4.3.2 at commit `37b6a132`), next to `conformance/pattern_ledger.toml` and `conformance/xfail_baseline.toml`. The 13 detect suites (193 cases) pass with zero xfail (README); the baseline lists 6 `safety_gates` cases, where the reference's over-budget verdict is a Python `re` timing fact that the linear regex-crate engine does not reproduce. Binary cases with full-entropy random noise are deliberately excluded from the corpus; their decode-stage parity gaps are covered by the `guard-core-engine` binary_noise_gate honesty tests instead.

## Honest gaps

Listed in `docs/configuration.md` ("What is not implemented"): no Redis-backed distributed rate-limit mode, no Redis event pipeline, and no decorator/protocol layer (that is the adapters' job). Divergences from the Python engine are listed in the CHANGELOG's "Known differences from Python" section.

## Footguns

- The facade crate re-exports the detect path, but the adapters still integrate through `guard-core-engine` directly; follow their lead unless you only need the facade surface.
- `guard-core-python` stays `publish = false`: do not look for it on crates.io.
- No `.agents` skill; `docs/` (including `docs/configuration.md`) and AGENTS.md carry the documentation, and CLAUDE.md is a separate file, not a copy of AGENTS.md.
